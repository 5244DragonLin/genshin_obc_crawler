# genshin_obc_crawler：原神观测枢图鉴导出工具

基于纯 Python 标准库调用米游社「观测枢」（原神官方 WIKI）的公开接口，一条命令导出**全部 26 类图鉴**（JSON）：角色、武器、圣遗物、敌人、食物、书籍这六类按信息建模，外加快捷导航上的材料、家具、秘境、成就、名片、任务、卡牌、影音回廊等 20 类；角色图鉴另出每人一篇 Markdown，词条封面随产物落盘。

## 💡为什么需要？

- 观测枢词条正文是富文本 HTML，技能倍率表、突破材料、命之座全埋在模板组件里，想按「元素」「星级」「部位」检索只能自己拆
- 信息藏得深：敌人招式动图、掉落物、生命值与抗性是分开的三块面板，一道菜的各个品级（奇怪 / 普通 / 美味 / 特殊料理）各占一个组件，整本书的卷信息与正文还分开存放、顺序互不相干
- 接口响应里大量字段是「字符串化的字典/列表」（服务端直接 `str()` 后塞进 JSON），不专门处理拿到的全是转义文本
- 老的词条详情接口只覆盖未迁移的旧词条，新词条请求会报「内容不存在」，需要走新平台接口并统一新旧数据
- 站点首页「快捷导航」挂着 32 个入口，背后是 26 个可抓的频道，逐个写解析脚本是无底洞
- 站点随版本更新，想要最新内容就得能随时重跑

**genshin_obc_crawler 解决这些问题**：把字符串化字段还原成结构、把组件模板还原成字段，一次运行落盘成可直接检索的 JSON 与 Markdown。

## ⭐亮点

- **零依赖**：仅 Python 标准库，3.8+ 直接运行
- **直连接口**：读官方 JSON 接口，不渲染页面、不解析 DOM；正文走 hoyowiki 新平台，新旧词条都能取到
- **26 类图鉴全覆盖**：站点快捷导航上的频道一个不落；前六类按信息建模（角色天赋倍率表、敌人抗性脚注、食物各品级、书籍分卷对齐），其余 20 类走统一结构——顶层检索字段 + 按站点顺序的正文区块
- **一套通用建模吃下 20 个频道**：材料、家具、秘境、成就、名片、任务、卡牌、影音回廊的正文都是同一套组件的不同组合，用一张「组件 → 区块」映射表统一处理；每个频道的差异只在「哪个筛选标签映射成哪个键」，写在分类表里，不写死代码
- **聚合频道自动分家**：千星奇域（756 条）、卡牌图鉴（778 条）、影音回廊（1030 条）在站点上是聚合频道，一次返回全部子频道卡片；产物按 `channel` 标明来路（衣装套装 / 角色牌 / 过场动画……），并对站点漏挂标签的卡片按子频道列表补齐归属
- **敌人数值带脚注**：生命值、相对生命值、抗性都挂着站点的 `[1]`「本数据为实测」这类注释，正文保留标记、注释单列到 `notes`，`[1]` 有处可查
- **书籍按卷自动对齐**：卷信息与全文在正文里分开存放且顺序打乱，卷名还有「卷一 / 第一卷 / 卷三 / 其之一 / 上本」几种写法，按卷名、正文首行、卷序三级对齐后按卷序重排
- **预告词条按频道区别对待**：角色的「米提亚【预告】」是未上线占位（正文全是「待更新」）直接跳过；影音回廊的「角色预告 PV」是正经片名，照收
- **并发抓取 + 增量维护**：默认 16 路并发，按内容指纹对账，没变的不重写文件，每轮新增/更新/移除写进 `changes.json`；中断后直接重跑即可

图片字段有两类：`icon` / `portrait` 是站点的原始地址，`cover` 是落盘后的相对路径。角色的 `cover` 指向 `assets/character/立绘/` 下的立绘，个别没有立绘的角色（如「奇偶」）`cover` 为 `null`。武器与圣遗物没有立绘，`cover` 指向各自目录下按名字命名的图标。路径分隔符随操作系统，Windows 下是反斜杠。

角色导出的 136 条不含未上线角色：站点会为已公布未上线的角色挂「米提亚【预告】」这样的占位词条（正文全是「待更新」），本项目按标题里的「预告」标记识别后跳过。

完整键名含义见 [docs/字段说明.md](docs/字段说明.md)：英文键是项目定的语义化键名，中文键是站点原文的表格行标题（如 `basic` 里的 `生日`、`set_effects` 里的 `2件套效果`），按原样保留、不做翻译。

## 🚀快速开始

### 1. 克隆项目

```bash
# Gitee 镜像（国内访问快）
git clone https://gitee.com/yhl5244/genshin_obc_crawler.git

# GitHub 原仓库
git clone https://github.com/5244DragonLin/genshin_obc_crawler.git

cd genshin_obc_crawler
```

### 2. 安装依赖

```bash
pip install -r requirements.txt   # 仅标准库即可运行，装了 PyYAML 解析配置更稳
```

### 3. 配置文件

复制一份配置，改掉输出目录（不复制也能跑，默认输出到 `output/`）：

```bash
cp config.example.yaml config.yaml
```

### 4. 运行

```bash
# 按 config.yaml 的开关导出（默认只开前六类）
python src/main.py

# 导出全部 26 类
python src/main.py --only 全部

# 只导指定的几个分类
python src/main.py --only 材料 家具 秘境 --out "E:/BaiduSyncdisk/其他/原神观测枢图鉴"

# 每类只抓 5 条试跑，先看结构对不对
python src/main.py --only 成就 名片 --limit 5

# 先看规模再决定是否落盘
python src/main.py --dry-run
```

## ❓️FAQ

**抓取需要登录或 Cookie 吗？**

不需要。两个接口都是公开 GET，本项目没有账号相关逻辑。

**26 类全量有多少条？跑一次要多久？**

约 1.49 万条正文，其中材料 2052、家具 2398、NPC 与商店 2376、成就 1614、任务 1099、影音回廊 1030、卡牌 778、千星奇域 756，其余几百条。只是看规模不落盘时用 `--dry-run`。

并发默认 16 路，取值来自实测：逐档提升（1/2/4/6/8/12/16，再到 24/32/48、64/96），每档取 30~40 个此前未请求过的词条，关掉缓存与重试让限流当场暴露，累计约 560 次请求。

| 并发 | 8 | 12 | 16 | 24 | 32 | 48 | 64 | 96 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 吞吐（条/秒） | 17.8 | 31.4 | 40.3 | 40.1 | 63.0 | 96.1 | 46.6 | 52.6 |
| 平均延迟（秒） | 0.41 | 0.32 | 0.33 | 0.52 | 0.33 | 0.32 | 0.44 | 0.40 |

到 96 路为止没有出现任何失败：没有 429，没有非零返回码，没有连接重置，单条最长 0.86 秒。吞吐在 48 路见顶，64 以上回落到 47~53 条/秒，说明瓶颈此时已经回到本机而非服务端。据此取 16：对公共接口留有可观余量，六类全量 1284 条约 34 秒。要更快可调到 32，不建议超过 48；想进一步降低对服务端的压力时填 1，回到逐条串行。

**新加的 20 类为什么键名和前六类不一样？**

前六类信息密度高、结构稳定，值得按字段精细建模（天赋倍率表、分卷对齐、抗性脚注）；其余频道的正文都是同一套组件的不同组合，逐频道写解析规则既写不完也难维护。所以它们走统一结构：**顶层放能检索的字段**（星级、类型、获取方式、地区……），**正文按站点顺序进 `sections`**，每块用 `kind` 标类型、`tab` 保留站点的模块名。想按「秘境类型」筛选就查 `types`，想读秘境说明就取 `sections` 里 `kind` 为 `text` / `table` 的那块。

**千星奇域、卡牌图鉴、影音回廊的条目怎么区分来路？**

这三类是站点上的聚合频道，列表接口一次返回全部子频道卡片。产物里每条记录带 `channel`（衣装套装 / 衣装部件 / 角色牌 / 过场动画 / 原神OST……）。绝大多数卡片 `ext` 里带 `c_<子频道id>` 标记，少数站点没写标签（千星奇域 12 条、影音回廊 5 条），程序按子频道的列表逐个子抓一遍补齐。

**跑完发现文件没变，是没抓到吗？**

不是。产物按内容指纹比对，站点那边没有改动就不会重写文件。导出到一半中断也不用重来，直接重跑即可。要看本轮检查了多少、有没有变化，看日志末尾的「本次变化」一行和产物目录的 `changes.json`。

**接口改了字段怎么办？**

接口地址与频道 id 集中在 `src/obc_api.py` 与 `src/catalogs.py`，改版时只需调这两处：频道 id 变了改 `catalogs.py` 的 `channel`，组件的 `component_id` 或字段形态变了改 `component_blocks.py` 的对应 handler。前六类的解析规则在各自的 `*_model.py`。想强制重新抓取而不比对旧产物时用 `--refresh`。
